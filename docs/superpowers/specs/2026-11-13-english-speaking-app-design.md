# 영어 말하기 연습 앱 — 설계 문서

작성일: 2026-11-13
상태: 초안 (사용자 승인 대기)

## 1. 목적과 이유

- 사용자는 영어 문서는 자주 쓰지만 **영어로 말해 본 경험이 거의 없어서** 말하기가 처음부터 어렵다.
- 목표는 특정 시험이 아니라 **전반적인 말하기 실력 향상**이다. 상황은 일상, 여행, 비즈니스 등 다양하다.
- 이 앱의 핵심은 새 지식을 가르치는 것이 아니라 **이미 아는 영어(글쓰기 실력)를 실시간으로 입 밖에 꺼내는 연습**이다.
- 사용 장소는 **집**과 **직접 운전하는 자동차 안**이다.
- 스픽(Speak) 같은 앱에서 아이디어를 얻었지만, 이름·디자인·캐릭터 등 스픽의 브랜드는 따라 하지 않는다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 아이폰에서 홈 화면 아이콘으로 실행되는 말하기 연습 앱
- 집 모드: 단계적 도움(쓰고→말하기, 힌트 보고 말하기, 바로 말하기)과 화면 교정
- 차 모드: 화면을 보지 않고 소리와 음성 명령만으로 연습
- 대화 기록 저장, 집에서 복습, 자주 틀린 표현 재출제
- 운영 비용 0원

**비목표 (지금은 하지 않음)**
- 앱스토어 출시, 다른 사람과 공유, 로그인·계정
- 음소 단위의 정밀한 발음 점수 (설명형 피드백만 제공)
- 레벨 시험, 정해진 커리큘럼
- 카플레이 화면 지원 (웹앱으로는 불가)
- 실시간 음성 스트리밍 대화 (나중에 업그레이드 후보, 6장 참고)

**실패 조건 (동작하더라도 실패로 보는 경우)**
- 차 모드에서 운전 중에 **화면을 보거나 터치해야 하는 순간**이 생기는 것
- 비용이 발생하는 것 (유료 API·유료 호스팅 필요)
- 초보자에게 대화 중간마다 교정을 끼워 넣어서 말하는 흐름을 끊는 것

## 3. 제약 조건

- 휴대폰: **아이폰**, 브라우저: 사파리. 개발 PC: **윈도우** (맥 없음)
- 앱 형태: **PWA**(홈 화면에 추가한 웹앱). HTTPS 필수(마이크 권한 때문)
- 혼자 사용. 데이터는 휴대폰 안에 저장
- AI: **Gemini API 무료 등급**. 무료 등급은 입력 데이터가 구글 서비스 개선에 쓰일 수 있으므로 앱 안에 짧게 안내한다
- 아이폰 정책: 소리 재생과 마이크는 **처음 한 번 사용자 터치**가 있어야 시작된다
- 아이폰에서 웹앱은 **화면 맨 앞에 떠 있고 화면이 켜져 있을 때만** 마이크가 계속 동작한다
- **차 모드는 내비게이션·음악 앱 없이 쓴다** (사용자 확인). 앱이 운전 내내 화면 맨 앞에 있어도 된다
- **차 모드에서는 물리 버튼(핸들·블루투스 재생 버튼 포함)도 쓰지 않는다** (사용자 확인). 시작 이후 모든 조작은 소리로만 한다

## 4. 검토한 방법과 선택

| 방법 | 내용 | 장단점 |
|---|---|---|
| **A. 웹앱 + Gemini 무료 API (선택)** | 녹음 → 말 멈춤 감지 → Gemini에 음성 전송(받아 적기·대답·교정) → 아이폰 내장 음성으로 읽기 | 홈 화면 앱으로 실행 가능, 기능을 자유롭게 넣을 수 있고 구조가 단순하다. 대신 대답까지 1~3초 지연, API 키 1회 입력 필요 |
| B. Claude Artifact | claude.ai 안의 웹페이지 | API 키가 필요 없고 가장 빠르게 만들 수 있다. 하지만 로그인한 claude.ai에서 열어야 하고, 차 모드(화면 계속 켜기, 손 안 대고 계속 듣기)가 동작할지 불확실하다 |
| C. Gemini Live API (실시간 음성) | 통화처럼 실시간 음성 대화 | 가장 자연스럽고 빠르다. 하지만 구현이 복잡하고, 무료 한도·세션 길이 제한이 불확실하며, 교정 기록을 따로 구현해야 한다 |

**선택: A.** 사용자가 A를 골랐다. 차 모드 응답이 느리다고 느껴지면 나중에 차 모드의 대화 부분만 C로 바꾸는 것을 검토한다.

## 5. 정해진 사항

### 5.1 연습 고르기 (공통)
- 카테고리: **일상 / 여행 / 비즈니스**. 각 카테고리에 상황 목록이 있다 (예: 카페 주문, 호텔 체크인, 회의에서 의견 말하기)
- **자유 대화**: 주제를 정하지 않거나 사용자가 주제를 직접 말한다
- 비즈니스에는 "이메일 문장을 회의 말투로 바꿔 말하기" 연습을 넣는다 (사용자가 영어 문서를 자주 쓰기 때문)
- 처음 상황 목록은 적게 시작한다. AI로 늘릴 수 있다

### 5.2 대화 한 턴의 흐름 (방법 A)
1. 사용자가 말한다 (녹음)
2. 앱이 소리 크기로 **말이 끝난 것을 감지**한다 (일정 시간 조용하면 끝)
3. 녹음을 Gemini에 보낸다. 한 번의 호출로 아래를 구조화된 형태(JSON)로 받는다:
   - 사용자가 말한 내용 받아 적기
   - AI 상대역의 다음 대사
   - 더 자연스러운 표현 제안 (있을 때만)
   - 발음에 대한 짧은 설명형 피드백 (있을 때만)
   - 사용자가 음성 명령을 했는지 여부 (차 모드)
4. AI 대사를 아이폰 내장 음성(speechSynthesis)으로 읽는다
5. 다시 1로 돌아간다

### 5.3 집 모드
- **단계적 도움** (사용자가 단계를 직접 고른다):
  1. **쓰고 → 말하기**: 대답을 먼저 글로 쓰고, 그것을 소리 내어 말한다
  2. **힌트 보고 말하기**: 필요할 때 한국어 힌트나 문장 시작 틀을 눌러서 본다
  3. **바로 말하기**: 도움 없이 대화한다
- 교정은 **대화 중에 끊지 않고**, 대화가 끝난 뒤 모아서 보여준다. 대화 중에는 각 턴 옆에 작은 표시만 둔다
- 말하기 버튼은 화면 터치 방식이어도 되고, 차 모드처럼 자동 감지여도 된다

### 5.4 차 모드 (운전 중, 화면 없이)
- **출발 전에** 상황을 고르고 시작 버튼을 누른다. 그 뒤로는 손을 쓰지 않는다
- 화면이 꺼지지 않도록 유지한다 (Screen Wake Lock)
- 말이 끝나면 자동으로 감지해서 AI가 대답한다
- **음성 명령** (한국어와 영어 둘 다 알아듣는다):
  - "다시 말해줘" / "Repeat": 방금 AI 대사를 다시 들려준다
  - "천천히": 더 느리게 말한다
  - "한국어로": 방금 문장의 뜻을 한국어로 알려준다
  - "힌트": 대답할 문장을 먼저 들려주고, 사용자가 따라 말하게 한다
  - "다음 상황" / "그만": 주제를 바꾸거나 연습을 끝낸다
- 한국어 힌트와 안내는 **소리로** 준다
- 교정은 운전 중에는 **짧게 말로만** 알려주거나 생략하고, 자세한 내용은 기록에 남긴다
- **느긋한 속도**: 사용자가 오래 말이 없어도 재촉하지 않는다. 한동안 조용하면 "계속할까요?"라고 한 번만 묻는다
- **인터넷 끊김**: 소리로 알려주고, 다시 연결되면 이어서 진행한다
- **차례대로 말하기**: AI가 말하는 도중에는 듣지 않는다. AI가 말을 마친 뒤에 사용자가 말하고, 음성 명령도 그때 한다. 끼어들기는 지원하지 않는다 *(작성자가 정한 사항: 차 스피커 소리가 마이크로 다시 들어가는 문제를 피하기 위해)*
- **전화가 오거나 화면이 잠기면** 연습을 일시정지하고, 다시 앱으로 돌아와 터치하면 이어서 한다 (운전이 끝난 뒤의 동작)
- **무료 사용 한도 소진**: 운전 중에 한도가 다 되면 "오늘 무료 사용량이 끝났어요"라고 소리로 알리고 연습을 끝낸다. 한 턴에 API 호출은 한 번만 한다 *(작성자가 정한 사항)*
- 소리는 블루투스로 차 스피커에서 나온다 (아이폰 기본 동작)

### 5.5 기록과 복습
- 모든 대화(차 모드 포함)를 휴대폰 안에 저장한다
- **글만 저장한다** (받아 적은 내용, AI 대사, 교정, 발음 피드백). 사용자 목소리 녹음은 Gemini에 보낸 뒤 저장하지 않는다 *(작성자가 정한 사항: 저장 공간과 백업 크기 문제를 피하기 위해. 사용자가 원하면 나중에 추가)*
- 복습 화면: 날짜별·모드별 대화 목록. 각 턴마다 내가 한 말, 더 자연스러운 표현, 발음 피드백을 보여준다
- **자주 틀린 표현**을 모아서, 다음 연습의 AI 대화에 다시 나오게 한다
- **백업 내보내기 / 가져오기** (파일)

### 5.6 설정
- 처음 실행 시 **Gemini API 키 입력** → 휴대폰 안에만 저장한다 (코드에 넣지 않는다)
- 무료 등급 데이터 사용 안내
- 아이폰 "향상된 음성/고품질 음성" 다운로드 방법 안내
- AI 음성 속도 조절

## 6. 위험 요소와 먼저 확인할 것 (시험판)

본격적으로 만들기 전에 **작은 시험판으로 실제 아이폰에서 확인**한다:
1. 홈 화면에 추가한 웹앱에서 마이크 녹음이 되는지
2. 차 모드에서 화면이 계속 켜져 있는지 (Wake Lock)
3. 녹음 → 소리 재생 → 다시 녹음이 손을 대지 않고 계속 이어지는지 (아이폰의 오디오 전환 문제)
4. 소리 크기로 말 끝을 감지하는 방식이 차 소음 속에서도 쓸 만한지
5. Gemini 무료 등급으로 음성 입력과 구조화된 응답이 되는지, 응답 시간은 어떤지

**3번(손 안 대고 계속 이어지기)이 실패하면**: 물리 버튼으로 대신하지 않는다 (사용자 결정). 대신 **차 모드의 대화 부분을 C안(Gemini Live API, 실시간 음성)으로 바꾸는 것을 검토**한다. Live API는 하나의 연결 안에서 듣기와 말하기를 함께 처리하므로 녹음↔재생 전환 문제를 피할 수 있다. C안으로 바꿀 때는 Live API의 무료 한도와 세션 길이를 먼저 확인한다. 집 모드는 A안 그대로 둔다.

그 밖의 항목이 실패하면 이 설계로 돌아와서 고친다.

## 7. 만드는 사람에게 맡기는 것

- 프레임워크 선택 (순수 JS, Preact, React 등)과 빌드 도구
- 저장 방식 (IndexedDB 등)
- Gemini 모델 이름과 프롬프트 세부 내용 (무료 등급에서 음성 입력이 되는 최신 Flash 계열 권장)
- 말 끝 감지의 기준값 (조용한 시간, 소리 크기)
- 무료 호스팅 선택 (GitHub Pages 또는 Cloudflare Pages)
- 화면 디자인 세부 사항 (단, 차 모드 시작 화면은 큰 버튼 하나로 단순하게)
- 처음 넣을 상황 목록의 구체적인 내용
